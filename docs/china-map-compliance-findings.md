# TrailCraft 中国区地图与轨迹合规：初步发现

> **法律提示：** 本文是基于公开资料的产品与技术分析，不构成法律意见。面向公众开放前，应由具备资质的中国律师或测绘合规顾问，结合实际主体、发布地区、底图合同、服务器位置和功能清单出具或复核意见。

## 已核验的公开资料

司法部转载的《地图管理条例》互联网地图服务解读指出，面向公众提供**地理位置定位、地理信息上传标注和地图数据库开发**等服务，属于互联网地图服务的重点监管范围；相关服务应依法取得相应测绘资质。该解读还说明，从事互联网地图服务时，存放地图数据的服务器应设在中华人民共和国境内，并应建立地图数据安全管理制度与保障措施。[1]

这对 TrailCraft 的含义是：产品不能因为源代码为“纯前端”或轨迹默认保存在浏览器，就当然被视为没有地图合规义务。只要公众可在产品中看到、上传、标注或传播带空间位置的路线内容，实际功能、底图来源、服务提供主体、服务器与数据流向都需要与有资质的地图服务路径和适用监管要求匹配。

## 当前代码与风险边界

原项目当前使用 MapLibre 作为二维展示引擎，并请求 OSM、Esri 影像/地形和可选 MapTiler 资源；还允许 GPX/KML/FIT 轨迹导入、CP 节点标注、照片 EXIF GPS 锚定、二维/三维地图展示和自包含网页/视频导出。[2] [3] 在中国区直接对公众发布时，以下功能不能仅按海外底图能否访问判断可发布性。

在 2026-08-19 从当前非中国大陆环境进行的基础连通性探测中，OSM 瓦片、Esri 影像瓦片和 Esri 地形端点均返回 HTTP 200；MapTiler 地形端点因未配置 Key 返回 HTTP 403。此结果只能说明这些端点在当前环境可响应，**不能证明中国大陆直连网络的速度、稳定性、可用性或商业发布许可**。原项目文档同样注明，其 Esri/OSM 测试经代理完成，不代表真实国内直连。[2]

| 业务功能 | 初步合规影响 | 首发前的行动 |
| --- | --- | --- |
| 仅本地解析轨迹、无底图或抽象高程曲线 | 轨迹仍可能包含精确位置数据；风险相对较低，但需明确本地处理、无服务器上传和数据删除方式。 | 默认本地处理，显著说明数据去向与浏览器清除路径。 |
| 调用在线底图和地形 | 底图许可、地图内容、审图信息、服务协议及中国区可用性均应核验。 | 选择已明确支持中国区公开 Web 使用的合规地图服务商/授权方案；展示必要版权、审图与服务标识。 |
| 上传轨迹、照片 EXIF、CP 标注 | 涉及位置数据与个人信息，并可能触及地理信息上传标注的服务边界。 | 首发保持浏览器内处理；如未来上传、分享或多人协作，需重新进行数据、资质和服务器合规评估。 |
| 公开分享路线、导出交互地图、赛事页面 | 从个人工具变为可传播的地图内容服务，审核与发布风险显著增加。 | 首发禁用公开托管分享；导出物采用本地下载，并对包含地图底图的导出功能单独核验。 |
| 坐标转换 | 国内地图常涉及 GCJ-02/BD-09 与 WGS-84 的展示一致性，错误转换会造成路线偏移与用户安全风险。 | 统一内部坐标策略，记录来源和转换；在国内底图切换时做可视化偏移验收。 |

## 首发范围建议

建议将首发定义为“**本地优先的路线工作台**”：用户在浏览器端导入轨迹、进行赛前编辑和计算，并将结果下载到本机；不提供账户、云端项目、公共轨迹库、公开链接、多人协作或用户上传内容的服务器托管。此范围仍应采用合法且面向中国区可使用的底图/地形路径，并在产品内完整展示必要版权和服务标识；但它避免在首发就建立位置数据收集、地图数据库和公开 UGC 服务。

三维巡游、视频以及带底图的交互网页导出需要作为单独的上线门槛：应首先确认地图服务许可是否覆盖离线导出、屏幕/视频/HTML 分发和对外传播，不能把在线地图瓦片的可显示性等同于可再分发权利。

## 待决策与待核验事项

1. 确定将作为对中国区用户实际可见底图的服务商与合同/开发者协议；不要以当前 OSM、Esri 或海外服务的匿名公共 URL 作为商业首发的唯一依据。
2. 确认面向公众的发布主体、部署区域、备案要求和地图服务器/数据处理位置。
3. 请测绘合规顾问按最终功能清单判断是否需要以持证地图服务商能力接入、是否存在审图号展示义务以及导出/分享的限制。
4. 编写隐私说明，覆盖轨迹、CP、照片 EXIF、浏览器 IndexedDB、第三方瓦片请求、导出文件和用户自主删除。
5. 在真实中国网络以及目标手机、桌面浏览器中测试地图可用性、坐标偏移、归属标识和无地图降级流程。

## 中国区地图接入的技术结论

Manus 静态模板内置的是 Google Maps 前端组件。虽然它可提供基础地图能力，但对于 TrailCraft 的中国区公开发布，它不应被默认选为正式底图路径：当前应用需要中国区地图服务商的合同/许可、坐标兼容、服务可用性以及必要的地图版权展示一并确认。

高德开放平台的官方文档显示，其地图 JS API 面向 Web 平台，调用前需要开发者账户、Web（JS API）Key 和安全密钥；安全密钥文档明确建议通过代理服务器转发，并推荐把安全密钥留在服务器端。[4] [5] 因此，若最终采用高德地图作为中国区在线底图，TrailCraft 不宜维持为“只有静态前端、无受控后端”的最终形态：至少需要一个受控的后端/代理与服务器端密钥配置，并在获得地图服务商允许后使用绑定正式域名的 Key。

这并不等于首发必须把用户轨迹上传到服务端。推荐的折中架构是：**轨迹解析、编辑、CP、配速计算、照片 EXIF 处理和工程存档继续在浏览器本地完成；后端仅承担地图服务安全代理、必要的合规配置和公开静态页面托管。** 当用户选择公开分享、云端备份或赛事协作时，才以清晰授权开启新的服务器端位置数据流。

## 建议的中国区首发架构修订

| 层级 | 首发设计 | 原因 |
| --- | --- | --- |
| 浏览器应用 | 本地读取 GPX/KML/FIT；本地 IndexedDB 存档；本地计算与本地导出。 | 最小化轨迹与 EXIF 位置数据上云，保留原产品隐私优势。 |
| 地图视图 | 用经审查的中国区地图服务商 Web SDK 取代当前海外瓦片默认路径；在应用中显示服务商归属和必要审图信息。 | 为公众地图展示提供更可控的许可、坐标与网络基础。 |
| 受控服务层 | 保存地图安全密钥、限制请求来源、承载安全代理与服务配置；不默认接收原始轨迹。 | 对齐地图供应商的密钥保护建议，避免在公开静态包中暴露安全凭据。 |
| 公开分享与云端功能 | 首发关闭；后续单独设计账户、授权、数据保留、删除、审查和地图合规路径。 | 不把个人本地工具直接扩展为位置数据 UGC 平台。 |
