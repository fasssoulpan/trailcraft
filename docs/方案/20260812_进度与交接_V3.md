## 二、V2 之后新增的内容

### 2.1 P2 收尾(Q4/Q5)

- **确定性逐帧渲染管线 + H.264 MP4**(WebCodecs + mp4-muxer),虚拟时间驱动,与实时帧率解耦;不支持时降级 MediaRecorder 并如实标注为预览级
- **多画幅**:16:9(1080p/4K)/ 9:16 / 1:1 / 3:4,**竖屏使用独立排版**而非横屏裁切
- **合规署名片尾**:按实际使用的地形/影像提供商生成,不臆测
- P2 验收记录:`trailcraft/docs/P2-验收记录.md`

### 2.2 表现分速算模式

不需导入轨迹,手填距离/爬升/下降/用时即可算表现分,附 **39 场赛事规格预设**(OCC/CCC/UTMB/崇礼/港百/柴古唐斯等,移植自 cyber-trail-hud)。同时按 10km(长赛道)或 5km(短赛道)分段列出**预估分段用时与累计用时**,时间分配走 P0 已有的配速模型(计入爬升/下降/疲劳),再整体缩放使各段之和等于输入用时。

界面明确写出假设:无真实轨迹时爬升按里程均匀分布,这是配速参考而非针对该赛道坡度剖面的预测。

### 2.3 手绘路线(`v0.4.0`)

- 工具箱内新增:点击加点、拖拽移顶点、右键删除、双击完成;实时虚线预览 + 橡皮筋线 + 里程读数
- 产出标准 `Track`,走 `applyOp` **可撤销**;之后分割/拼接/抽稀、CP 锚定、导出、3D 巡游全部可用
- **补全高程**:从已在用的 Esri 免费全球地形采样真实高程,补完后剖面、爬升、关门预警、3D 巡游才真正可用
- 加密间隔 30m(与 DEM 分辨率同量级);超长路线会**拒绝并提示**而非静默截断或卡死页面
- 选中轨迹现在会**置顶显示**(此前可能被后导入的轨迹压在下面)

### 2.4 其他修复

| 缺陷 | 影响 |
|---|---|
| mp4-muxer 写出回调漏 `position` 参数 | 导出的 MP4 会损坏(播几秒后散架);真人浏览器测试才暴露 |
| 手绘拖拽后 `dragMoved` 永不复位 | 3px 阈值与 MapLibre 的 `clickTolerance` 完全相同,导致 `click` 不触发、复位路径永不执行,**下一次点击被静默吞掉** |
| 拖拽在地图外松手 → `dragPan` 永久禁用 | MapLibre 的 `mouseup` 只从画布容器派发,松手在侧栏上就收不到;用户从此无法拖动地图且无任何提示 |
| 抓住顶点未移动即松开会叠加重复顶点 | 评审时才发现,原代码只看位移、不看 mousedown 命中了什么 |
| 稠密化无上限 | zoom 3 下两次点击可相距数千公里 → 数万个点在主线程同步生成,页面卡死 |
| 署名片尾期间进度条消失 | "credits" 阶段加进了文字标签却漏了进度条判断 |
| 校准测试自带常数副本 | 连续三次重拟合未同步,测试静默失效 |
| dev 服务器只监听 IPv6 | `localhost` 解析到 127.0.0.1 时打不开,易误判为端口冲突 |

**手势状态机已从 React 组件抽成纯模块**(`src/map/drawGesture.ts`)并单测覆盖——上述两个 Critical 缺陷能长期存活,正是因为逻辑藏在无法测试的组件里。

### 3.2 路网吸附——**已查明受阻,未实施**

你提到「二维平面图模式下有路网」。当前 2D 底图是 **OSM 栅格瓦片**,路网是像素而非可查询几何,**无法程序化吸附**。真正的吸附需要矢量步道数据,标准来源是 Overpass API。

**实测四个 Overpass 镜像全部连接失败**(overpass-api.de、overpass.kumi.systems、overpass.private.coffee、overpass.osm.jp,均 HTTP 000)。在拿不到数据源、也无法验证的前提下,我没有实施——本项目已被"未经真人验证的功能"咬过两次(MapLibre Worker、mp4-muxer)。

要推进需先确认:你的网络能否访问 Overpass?若不能,备选是换矢量底图源,或自建 Overpass 实例。届时建议做的不只是"顶点吸附",而是**沿步道路径规划**(点几个途经点,路线自动沿真实步道走),那才是规划工具的核心价值,需要建图 + A* 寻路。顶点列表已保持为唯一数据源,将来加吸附只需重写顶点,不影响其他部分。

## 四、表现分模型现状

`PI = min(1000, C × (kme/hours)^K × (kme/270)^M × envFactor)`,`C=77.9, K=0.850, M=0.155`。`M/K = 0.182` → 隐含 Riegel 耐力指数 **1.18**(超长距离越野经验区间 1.10~1.20)。

等级阈值:精英级 680 / 优秀 500 / 良好 380 / 中等 200。

**校准依赖的假设(必读)**:
- **没有任何一位选手的官方单场 ITRA 分数**支撑;"国际精英落在 900~960"是我根据其实力水平的推断
- 崇礼 100/70/50km 三行**已排除**——爬升是按 168km 组比例估的,其中 70km 行算出均速 15.5 km/h(比 UTMB/OCC 冠军在同类地形上都快),物理上不可能。这一个虚假数据点曾绑架整个拟合,导致赢 UTMB 得 808 分而赢区域性 70km 得 954 分。剔除理由已写入 `calibration.ts` 代码注释,防止日后被不知情地加回
- 分段拟合**暂不做**:可核实的数值锚点只剩一个,增加分段只会拟合噪声。需要的是更多真实数据,不是更多参数

**最能提升准确度的数据**:各赛事官方单场 ITRA 得分;崇礼短组别实测赛道规格;2025 OCC 备用赛道实际规格;中段完赛者(非仅冠军)数据。

## 五、已知限制

- 视频录制降级到 MediaRecorder 时仍是预览级(WebM),UI 如实标注
- 表现分为社区逆向估算,**非官方 ITRA 积分**,界面已明示
- KMZ 不支持;拼接不支持拖拽排序;`splitAt` 后 CP 全部重锚到前半段
- 规划模式无等高线(该模式未加载高程数据)
- 坐标偏转为社区公开近似实现,国内商业发布前需做测绘法规合规评估
- **仍缺样本**:国内 App(两步路/六只脚等)导出的 GCJ-02 轨迹,P0 验收标准 2 因此仍标"部分"
