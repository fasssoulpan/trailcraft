## 一、本轮目标与边界

### 1.1 目标(P0 交付物,验收标准沿用方案 V2.1 第七章)

| # | 交付物 | 验收标准摘要 |
|---|--------|--------------|
| 1 | GPX/FIT/KML 解析 | 三格式各 5 条真实赛道轨迹导入成功率 100%;1 万点轨迹解析 < 2 秒 |
| 2 | 坐标系识别与转换 | GCJ-02/WGS-84 混合导入自动识别正确率 ≥ 95%,转换残差 < 3m |
| 3 | 轨迹工具箱(基础) | 分割/拼接/反向/异常点剔除/抽稀,全部可撤销,原始轨迹不改写 |
| 4 | 剖面联动 | 地图与高程剖面双向悬停联动,延迟 < 50ms |
| 5 | CP 节点与分段 | 折返赛道 CP 锚定无错趟;分段爬升与官方数据误差 ≤ 8%(校准后) |
| 6 | 关门预警 | 各 CP 预计到达时间 + 红黄绿预警,配速参数可调 |

### 1.2 明确不做(留给后续阶段)

- 瓦片烘焙管线、PMTiles、3D 地形与巡游(P1)
- 信息叠加层、镜头模板(P2);电影渲染与视频导出(P3)
- Excel 路书、路网吸附纠偏、TrackSource 适配器、交互网页导出(P4)
- Tauri 桌面壳(P3/P4 视 ffmpeg 兜底需求再包)
- P0 底图:MapLibre 加载免费栅格底图(OSM 官方瓦片,开发期用途;可配置替换),不做自制风格化底图

## 二、技术选型(P0 实际落地清单)

| 层 | 选型 | 版本基线 | 许可 | 说明 |
|----|------|----------|------|------|
| 语言/构建 | TypeScript + Vite | TS 5.x / Vite 5+ | MIT | 严格模式(strict);ESM |
| UI 框架 | React | 18+ | MIT | 函数组件 + hooks |
| 状态管理 | Zustand | 4+ | MIT | 轻量,支持 undo/redo 中间件自研 |
| 地图渲染 | MapLibre GL JS | v4+ | BSD-3 | P0 仅用 2D;实例保留给 P1 3D terrain 复用 |
| 空间计算 | @turf/turf | 7.x | MIT | 距离/沿线取点等;测地重计算走 Web Worker |
| FIT 解析 | fit-file-parser | 最新 | MIT | GPX/KML 自研解析(fast-xml-parser 辅助) |
| XML 解析 | fast-xml-parser | 4.x | MIT | GPX/KML 的底层 XML 解析 |
| 本地存储 | idb(IndexedDB 封装) | 8.x | ISC | 工程文件、来源→坐标系映射记忆 |
| 高程剖面图 | 自研 Canvas 渲染 | — | — | <50ms 联动要求,自绘最可控,零依赖 |
| 坐标转换 | 自研 GCJ-02/BD-09 算法模块 | — | MIT 社区算法移植 | 精度 1~2m;纯函数,100% 单测覆盖 |
| 单元测试 | Vitest | 2.x | MIT | core 层全覆盖 |
| E2E 测试 | Playwright(按需) | 最新 | Apache-2.0 | 剖面联动等交互验收 |
| 代码规范 | ESLint + Prettier | 最新 | MIT | 提交前检查 |

坐标转换不引入现成 npm 包(多数无维护),按方案 V2.1 采用社区公开近似算法自研移植并保留出处注释,配已知点对测试用例。

## 三、代码架构

```
trailcraft/
├── src/
│   ├── core/              # 纯 TS 领域层,零框架依赖,全部可单测
│   │   ├── parsers/       # gpx.ts / kml.ts / fit.ts → 统一 Track 模型
│   │   ├── crs/           # wgs84/gcj02/bd09 转换 + 三级启发式识别
│   │   ├── geo/           # 测地距离、累计里程、沿线插值
│   │   ├── toolbox/       # 分割/拼接/反向/异常点剔除/抽稀(纯函数,输入输出新对象)
│   │   ├── stats/         # SG 平滑 + 阈值滞回爬升、分段统计、坡度三定义
│   │   ├── pace/          # Tobler / GAP / 实用档配速模型 + 关门预警
│   │   └── model/         # Track / CheckPoint / Project 类型与 GeoJSON 扩展 schema
│   ├── workers/           # Web Worker 入口(解析、重计算)
│   ├── state/             # Zustand stores + undo/redo(命令栈,非破坏性)
│   ├── map/               # MapLibre 封装:轨迹图层、CP marker、悬停事件
│   ├── profile/           # Canvas 高程剖面组件(渲染 + 命中检测)
│   ├── ui/                # React 组件(导入面板、工具箱、CP 编辑、预警表)
│   └── App.tsx
├── tests/                 # Vitest 单测(镜像 core 结构)+ fixtures 轨迹样本
├── e2e/                   # Playwright(按需)
└── docs/                  # 代码内技术笔记
```

**关键设计约束**(源自方案 V2.1):

1. **非破坏性编辑**:原始轨迹 immutable,一切工具箱操作产生新版本,命令栈支持撤销;
2. **内部统一 WGS-84**:导入时一次转换,显示与导出各自适配,内部数据永不因显示改写;
3. **爬升以轨迹自带高程为准**:P0 无 DEM,高程缺失段仅标注(DEM 回填留 P1);
4. **CP 锚定里程单调约束**:按输入顺序锚定索引递增,折返赛道不锚错趟;
5. **累计里程数组导入即预计算**并随工程持久化,剖面/分段/后续相机样条共用;
6. **schema_version** 从第一个工程文件就写入,时间字段 ISO 8601 含时区。

## 四、开发流程

### 4.1 里程碑拆分(M1~M6,对应验收标准逐项闭环)

| 里程碑 | 内容 | 验收方式 |
|--------|------|----------|
| M0 脚手架 | Vite+React+TS 工程、ESLint、Vitest、git 初始化、CI 本地脚本 | `npm run build`/`test`/`lint` 全绿 |
| M1 解析与模型 | GPX/KML/FIT 解析 → Track 模型;Worker 化;累计里程预计算 | 单测 + 1 万点性能测试 < 2s |
| M2 坐标系 | GCJ-02/BD-09 转换算法 + 三级识别 + 来源记忆 | 已知点对残差 < 3m;混合样本识别 ≥ 95% |
| M3 地图与剖面 | MapLibre 轨迹显示 + Canvas 剖面 + 双向悬停联动 | 手动验收 + 联动延迟量测 < 50ms |
| M4 工具箱 | 分割/拼接/反向/异常点剔除/抽稀 + undo/redo | 单测全覆盖;UI 操作可撤销 |
| M5 CP 与统计 | CP 编辑、单调锚定、分段统计、爬升阈值滞回与校准 | 折返样本无错趟;对照真实赛事数据误差 ≤ 8% |
| M6 配速预警 | 三档配速模型、关门时间红黄绿预警、参数面板 | 模型单测 + 样例赛道人工核对 |

每个里程碑:**编码(TDD)→ 自测 → 代码评审(code-reviewer 子代理)→ git commit + tag**。

### 4.2 开发方式

- **主会话统筹 + 子代理执行**:按里程碑将任务派发给子代理(subagent)并行/串行完成,每个里程碑完成后由 code-reviewer 子代理对照本文档评审;
- **TDD**:core 层(解析/坐标/统计/配速)先写测试再写实现——这些纯函数模块是数据可信度的根基;UI 层以手动验收 + 按需 E2E 为主;
- **测试数据**:tests/fixtures 内置合成轨迹(可控场景:折返、跳点、缺高程)+ 真实轨迹样本(需你提供或从公开渠道获取 GPX,验收标准要求每格式 5 条真实赛道)。

### 4.3 文件存储与版本规范(按你的要求)

- 根目录:`C:\Users\Administrator\Desktop\越野跑地图软件开发\`
- **文档**:根目录下按 `YYYYMMDD_名称_Vx.md/docx` 命名,只增不改(修订即升版本号),如本文档 `20260806_开发流程与选型_V1.md`;
- **代码**:`trailcraft\` 子目录,git 管理,里程碑完成打 tag(`p0-m1`…`p0-m6`,P0 完成打 `v0.1.0`);
- **实施计划**:确认本文档后另出 `20260806_P0实施计划_V1.md`(任务级拆解,子代理按此执行)。

## 五、风险与应对(P0 范围内)

| 风险 | 应对 |
|------|------|
| 坐标系自动识别在无参照荒野轨迹上误判 | P0 内置置信度阈值,不足时 UI 强制人工二选一对照(方案 V2.1 既定策略);识别器单测覆盖典型与边界样本 |
| 真实赛道轨迹样本不足,验收打折 | 先用合成 + 公开 GPX 顶上,清单中标注缺口,请用户补充两步路等平台导出样本 |
| OSM 官方瓦片在国内加载慢 | 底图 URL 做成可配置;仅影响开发体验,不影响 P0 验收项 |
| 1 万点轨迹 UI 卡顿 | 解析与重计算全部 Worker 化;地图渲染用抽稀副本,数据层保留全精度 |
