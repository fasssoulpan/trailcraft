### 借鉴与取舍

参考的两个来源都没有照搬:

- **你在 manus 上线的那个页面**——真正让它显得清爽的不是"浅色",是结构:卡片分组、每块「标题 + 一句说明 + 内容」、克制的单一强调色、留白。这几条都落地了,侧栏每个分组和面板现在都有一句说明文字。
- **归藏的 `fit-ride-studio`**——它是 AGPL-3.0,**只借鉴做法,没有复制它的 CSS 或类名**。借鉴的是指标网格与等宽数字(数值刷新时不再左右跳动)。

主色没有跟随任何一方:manus 页是 shadcn 蓝,`fit-ride-studio` 是黑底青柠。TrailCraft 用的是**步道标记橙**(全球包括国内越野赛道实体路标的颜色),配偏绿的中性灰(森林/地形感),而不是通用灰或骑行 App 的蓝灰。

### 深色仍是默认,浅色是一等主题

右上角有主题切换,选择会被记住。默认深色的理由是:软件的主界面是卫星图和三维巡游,巡游 HUD、CP 卡片、雷达本来就是深色叠加层——浅色做默认会让地图周围的界面天天跟地图打架。

## 二、明天请重点看这几处

**代码层面能自证的都已自证**(1114 测试、类型、构建、对比度、面板无遗漏)。**唯独"看起来怎么样"我无法验证**——沙盒里的预览面板不合成帧,而且它返回的样式数值被证实是错的(内联写死的颜色读回来是另一套主题的值;`data-theme` 明明是 light,选择器匹配却返回 false)。我一度据此认定浅色主题有 5 处对比度不合格,追查后发现全是测量假象,规则本身没问题。所以这部分只能由你来看。

```bash
npm run dev
```

打开 http://localhost:5199/ ,按顺序看:

1. **侧栏五个分组**——展开/收起是否记得住;每组的说明文字是否讲清了这组能干什么。这是本次改动最大的地方,也最需要你判断"是不是真的更好用了"。
2. **主题切换**(右上角)——切到浅色,看侧栏、表格、徽章、按钮是否都跟着变;**巡游模式的 HUD 和 CP 卡片应当保持深色不变**,这是故意的(见下)。
3. **数字是否等宽**——配速表、分段统计里的数字在刷新时不应左右抖动。
4. **规划/巡游模式切换**——切到巡游模式时,「规划」组会显示"手绘路线仅规划模式可用";切回规划,「视图」组会提示等高线/雷达需要巡游模式。看这两个提示是否准确、是否碍事。
5. **导出成片**——如果方便,导一小段视频,确认画面里的 HUD 和 CP 卡片跟屏幕上预览的**颜色一致**。

## 三、一个必须说明的技术约束

巡游 HUD、CP 卡片、巡游控制条、关键帧编辑器这几处**故意不跟随主题**,原因不是审美:

导出视频时,`src/overlay/captureDraw.ts` 会把同一套 HUD 重新画到导出画布上。Canvas 2D 读不到 CSS 变量,所以它自带一份颜色常量副本。如果 CSS 这边跟着主题翻转而它不翻,**屏幕上预览的画面就不再等于导出的成片**——而你正是对着预览在构图。

这次把这份重复关系:① 在两个文件里互相写明,② 用测试锁死(改动任一边而不改另一边,`CARD_META_COLOR equals --overlay-text-muted` 这类测试会红)。以前这份重复是**隐性**的,谁都可能无意改坏。

## 四、顺带修掉的两个既有问题
