## 一、路线变更及其依据

### 1.1 变更内容

方案 V2.1 第三章原定「MapLibre 3D 预览 + Three.js 电影模式」双渲染器路线,并明确放弃 CesiumJS。**P1 起改为 CesiumJS 单渲染器路线**,3D 地形与巡游相机直接移植自 `cyber-trail-hud`。

### 1.2 依据

方案 V2.1 放弃 Cesium 的理由是「其生态强绑定 Cesium ion 付费资产,自建 quantized-mesh 地形工具链过重」。`cyber-trail-hud/src/map/viewer.js` 证明该前提不成立:

| | 首选(需 Key) | 免费兜底(无需注册) |
|---|---|---|
| 地形 | MapTiler quantized-mesh | **Esri WorldElevation3D** |
| 影像 | MapTiler 卫星 / 天地图 | **Esri World Imagery** |
| 最终兜底 | — | `EllipsoidTerrainProvider`(平面) |

全程未使用 Cesium ion token。这直接消解了两项原始顾虑:

1. **无付费绑定**:Esri 免费全球 3D 地形无需注册,Cesium 本体 Apache-2.0;
2. **无需自建烘焙管线**:方案 V2.1 的 P1 主体工作量是「DEM→Terrain-RGB→PMTiles」GDAL 烘焙管线,采用在线地形服务后**整条管线可省略**。

### 1.3 保留与放弃

- **保留 TrailCraft P0 数据层**:解析、坐标系识别转换、几何、爬升统计、配速模型、工程持久化。这部分有 246 个单元测试与真实数据验证(距离与设备自报偏差 0.8~3.2%),严谨度高于参考实现,是本项目的核心资产。
- **移植 cyber-trail-hud 的 3D 层**:Cesium viewer 初始化与地形降级链、轨迹渲染、巡游相机引擎、HUD 叠加层。
- **暂不移植**:该项目的评分/ITRA/心率分区等分析模块(超出 TrailCraft 定位)、其对象数组数据模型(与 P0 列式模型冲突,见 §3.2)。

### 1.4 代价与后续债务

- 首屏体积:Cesium 约 3~4 MB(gzip 后),需代码分割,仅进入巡游模式时按需加载;
- **在线地形依赖**:与方案 V2.1「本地优先、离线可用」原则冲突。Esri/MapTiler 在国内访问速度未验证。→ 见 §6 风险 R1;
- **视频质量**:参考实现用 `MediaRecorder` 录屏,方案 V2.1 明确要求「与实时帧率解耦的确定性逐帧渲染」。P1 先做到录屏出片(与参考实现持平),逐帧管线列为 P2。

## 二、P1 目标与验收标准

### 2.1 交付物

| # | 交付物 | 验收标准 |
|---|--------|----------|
| 1 | Cesium 巡游模式 | 与 2D 规划模式共享同一 store;切换不丢失轨迹/CP/参数 |
| 2 | 3D 地形加载 | Esri 免费地形正常加载;无 Key 时不报错降级;地形不可用时降级为平面且提示 |
| 3 | 轨迹 3D 渲染 | 33 万点轨迹贴地渲染不卡顿(抽稀后 ≤ 8000 点);沿用 P0 的每轨迹颜色与粗细设置 |
| 4 | CP 三维标记 | P0 的 CP 按类型着色显示于 3D 场景,含序号与名称 |
| 5 | 巡游相机 | 跟随/俯瞰/自由三模式;1×~20× 倍速平滑无跳变;可暂停/拖动进度 |
| 6 | HUD 叠加层 | 实时里程/海拔/累计爬升/当前坡度;数据来源为 P0 统计模块,与 2D 剖面数值一致 |
| 7 | CP 卡片 | 接近 CP 时弹出名称/里程/海拔/关门时间 |
| 8 | 视频录制 | 1080p WebM 录制可用并下载;明确标注为「预览级」,4K/竖屏/逐帧一致留 P2 |
| 9 | 按需加载 | 不进入巡游模式时不加载 Cesium;首屏体积不因本阶段显著劣化 |

### 2.2 明确不做

- 逐帧确定性渲染管线、4K/竖屏输出(P2)
- 镜头模板库与关键帧编辑器(P2)
- PMTiles 离线包烘焙(暂缓,视 §6 R1 结论决定是否恢复)
- 风格化底图(暂缓,改用卫星影像)
- Excel 路书、交互网页导出(P3,原 P4)

## 三、技术设计

### 3.1 模块结构

```
src/
├── cesium/                      新增,全部按需加载
│   ├── viewer.ts                Viewer 创建 + 地形/影像降级链
│   ├── trackEntities.ts         Track(列式)→ Cesium 实体
│   ├── cpEntities.ts            CheckPoint → 3D 标记
│   ├── flythrough.ts            相机引擎(跟随/俯瞰/自由)
│   └── recorder.ts              MediaRecorder 录制
├── ui/
│   ├── FlyView.tsx              巡游模式容器(懒加载 Cesium)
│   ├── HudOverlay.tsx           HUD(独立 DOM 层,非 Cesium 内绘制)
│   └── ModeSwitch.tsx           规划 / 巡游 模式切换
└── state/appStore.ts            扩展巡游状态
```

HUD 走独立 DOM/Canvas 层而非 Cesium 内部绘制,与方案 V2.1「叠加层由独立 2D 层渲染后与 3D 帧合成」一致,也便于后续竖屏独立排版。

### 3.2 数据桥接(关键)

参考实现用对象数组 `points: [{lat, lng, ele, time, hr}, ...]`;P0 用 TypedArray 列式存储。**保留列式模型**——33 万点的对象数组在 V8 下内存开销约为列式的 5~10 倍,且 P0 全部统计模块依赖列式。

桥接层 `trackEntities.ts` 职责:
- 复用 P0 现有 `decimateIndices` 抽稀至渲染上限(3D 建议 8000,高于 2D 的 4000,因巡游会贴近观察);
- 抽稀后批量转 `Cartesian3.fromDegreesArrayHeights`(接受扁平数组,天然契合列式存储,无需构造中间对象);
- 时间轴用 P0 的 `points.time`;无时间戳的轨迹按累计里程等速合成虚拟时间(参考实现未处理此情况,而国内平台导出的规划轨迹常无时间)。

### 3.3 相机引擎

移植 `flythrough.js` 的三模式设计,改写为 TypeScript 并去除模块级可变状态(参考实现用模块级 `_state` 单例,不利于测试与多实例):

- **跟随**:相机位于运动点后上方,朝运动方向;
- **俯瞰**:正上方缓慢环绕,滚轮调距;
- **自由**:用户自由操控,运动点继续前进。

相机路径基于 P0 的 `cumDist`,以里程为参数而非帧序号,保证倍速变化时轨迹一致——这也是 P2 逐帧渲染能复用同一路径的前提。

### 3.4 HUD 数据源

HUD 数值全部来自 P0 已验证的统计模块(`stats/elevation.ts`、`stats/segments.ts`),**不在 3D 层另算一套**。验收标准第 6 条要求与 2D 剖面数值一致,即由此保证。

## 四、里程碑

| 里程碑 | 内容 | 验收 |
|--------|------|------|
| N1 | Cesium 接入、viewer 与地形降级链、模式切换与按需加载 | 巡游模式能打开,地形可见,首屏体积不劣化 |
| N2 | 轨迹与 CP 的 3D 渲染、数据桥接层 | 33 万点轨迹贴地渲染流畅,颜色/粗细沿用 P0 设置 |
| N3 | 巡游相机三模式、播放控制与倍速 | 1×~20× 平滑无跳变 |
| N4 | HUD 叠加层与 CP 卡片 | 数值与 2D 剖面一致 |
| N5 | 视频录制与收尾验收 | 1080p WebM 可下载;验收记录归档 |

每个里程碑:TDD(可测部分)→ 自测 → 代码评审 → commit + tag(`p1-n1` … `p1-n5`,完成打 `v0.2.0`)。

桥接层、抽稀、虚拟时间合成、相机里程参数化等纯逻辑必须单测;Cesium 渲染与相机视觉效果由浏览器验收。

## 五、与参考实现的差异清单

移植时的既定改动,避免实施中反复:

| 项 | cyber-trail-hud | TrailCraft P1 |
|---|---|---|
| 语言 | JavaScript | TypeScript(strict) |
| 数据模型 | 对象数组 | 保留 P0 列式 TypedArray |
| 状态管理 | 模块级单例 `_state` | Zustand store + 实例化引擎 |
| 解析 | @tmcw/togeojson + fit-file-parser 2.x | 保留 P0 自研解析器(性能已验证) |
| 坐标系 | 未处理 GCJ-02 | 保留 P0 自动识别与转换 |
| 爬升统计 | 自有实现 | 保留 P0 阈值滞回 + 官方校准 |
| 地形首选 | MapTiler(需 Key) | Esri 免费优先,Key 可选 |
| 视频 | MediaRecorder | P1 同左,P2 改逐帧 |

## 六、风险与应对

| # | 风险 | 影响 | 应对 |
|---|------|------|------|
| R1 | Esri / MapTiler 地形服务国内访问慢或不通 | 巡游模式不可用,且与「离线优先」原则冲突 | **N1 首先实测国内访问速度**;不达标则启用天地图影像 + 评估恢复 PMTiles 地形烘焙(方案 V2.1 原路线)。此项决定后续是否需要补做烘焙管线 |
| R2 | Cesium 包体积拖累首屏 | 2D 规划用户被迫下载 3D 引擎 | 动态 `import()` 分包,仅进入巡游模式时加载 |
| R3 | 33 万点轨迹在 3D 下卡顿 | 巡游不流畅 | 抽稀至 8000 点渲染;必要时按相机距离分级 |
| R4 | 录屏画质不达传播要求 | 核心交付物打折 | P1 明确标注「预览级」;P2 做逐帧管线,相机路径已按里程参数化以便复用 |
| R5 | 无时间戳轨迹无法驱动时间轴 | 规划轨迹不能巡游 | 按里程等速合成虚拟时间(参考实现缺此处理) |
| R6 | Cesium 与 React 18 严格模式下的重复挂载 | Viewer 泄漏 | 明确的创建/销毁生命周期,参照 P0 `MapView` 已验证的模式 |
