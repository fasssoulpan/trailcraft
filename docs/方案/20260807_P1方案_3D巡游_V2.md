## 一、路线变更及其依据

### 1.1 变更内容

方案 V2.1 第三章原定「MapLibre 3D 预览 + Three.js 电影模式」双渲染器路线,并明确放弃 CesiumJS。**P1 起改为 CesiumJS 单渲染器路线**,3D 地形与巡游相机直接移植自 `cyber-trail-hud`。

### 1.2 依据

方案 V2.1 放弃 Cesium 的理由是「其生态强绑定 Cesium ion 付费资产,自建 quantized-mesh 地形工具链过重」。`cyber-trail-hud/src/map/viewer.js` 证明该前提不成立:

| | 首选(需 Key) | 免费兜底(无需注册) |
|---|---|---|
| 地形 | MapTiler quantized-mesh | **Esri WorldElevation3D** |
| 影像 | MapTiler 卫星 / 天地图 | **Esri World Imagery** |
| 最终兜底 | — | `EllipsoidTerrainProvider`(平面) |

全程未使用 Cesium ion token。这消解了两项原始顾虑:无付费绑定(Esri 免费全球 3D 地形无需注册,Cesium 本体 Apache-2.0);无需自建烘焙管线(方案 V2.1 的 P1 主体工作量「DEM→Terrain-RGB→PMTiles」GDAL 管线可省略)。

**可达性实测(2026-08-07,本机经代理,不代表真实国内直连)**:Esri 地形 HTTP 200 / 1.10s;Esri 影像瓦片 HTTP 200 / 2.30s / 24KB;天地图超时失败;OSM 瓦片 200 / 3.37s。Esri 两项均通且快于现用 OSM。需在真实国内网络下复测。

### 1.3 保留与放弃

- **保留 TrailCraft P0 数据层**:解析、坐标系识别转换、几何、爬升统计、配速模型、工程持久化。246 个单元测试与真实数据验证(距离与设备自报偏差 0.8~3.2%),是本项目核心资产。
- **移植 cyber-trail-hud 的 3D 层**:Cesium viewer 与地形降级链、轨迹渲染、巡游相机引擎、HUD 叠加层。
- **暂不移植**:评分/ITRA/心率分区等分析模块(超出 TrailCraft 定位)、对象数组数据模型(与 P0 列式模型冲突,见 §3.2)。

### 1.4 代价与后续债务

- 首屏体积:Cesium 约 3~4 MB(gzip 后),需代码分割,仅进入巡游模式时按需加载;
- **在线地形依赖**:与方案 V2.1「本地优先、离线可用」原则冲突,见 §6 R1;
- **视频质量**:参考实现用 `MediaRecorder` 录屏,方案 V2.1 要求「与实时帧率解耦的确定性逐帧渲染」。P1 先做到录屏出片,逐帧管线列为 P2。

## 三、技术设计

### 3.1 模块结构

```
src/
├── cesium/                      全部按需加载
│   ├── viewer.ts                Viewer 创建 + 地形/影像降级链   ✅ 已完成
│   ├── terrainSelection.ts      提供商选择决策(纯函数,已单测) ✅ 已完成
│   ├── basemap.ts               底图样式切换(V2 新增)
│   ├── contours.ts              等高线图层(V2 新增)
│   ├── trackEntities.ts         Track(列式)→ Cesium 实体
│   ├── cpEntities.ts            CheckPoint → 3D 标记
│   ├── flythrough.ts            相机引擎(跟随/俯瞰/自由)
│   └── recorder.ts              MediaRecorder 录制
├── overlay/                     与渲染引擎无关的叠加层(V2 新增)
│   ├── radar.ts                 距离雷达绘制(纯计算 + Canvas)
│   └── radarMath.ts             量程档位与投影计算(纯函数,单测)
├── ui/
│   ├── FlyView.tsx              巡游模式容器(懒加载 Cesium)
│   ├── HudOverlay.tsx           HUD(独立 DOM/Canvas 层)
│   ├── LayerPanel.tsx           图层控制:底图 / 等高线 / 雷达(V2 新增)
│   └── ModeSwitch.tsx           规划 / 巡游 模式切换
└── state/appStore.ts            扩展巡游与图层状态
```

HUD 与雷达走独立 DOM/Canvas 层而非 Cesium 内部绘制,与方案 V2.1「叠加层由独立 2D 层渲染后与 3D 帧合成」一致,也便于后续竖屏独立排版。**注意**:独立叠加层不会进入 `canvas.captureStream()` 的录制画面,视频合成方式见 §6 R8。

### 3.2 数据桥接(关键)

参考实现用对象数组 `points: [{lat, lng, ele, time, hr}, ...]`;P0 用 TypedArray 列式存储。**保留列式模型**——33 万点的对象数组在 V8 下内存开销约为列式的 5~10 倍,且 P0 全部统计模块依赖列式。

桥接层 `trackEntities.ts` 职责:
- 复用 P0 `decimateIndices` 抽稀至渲染上限(3D 建议 8000,高于 2D 的 4000,因巡游会贴近观察);
- 抽稀后批量转 `Cartesian3.fromDegreesArrayHeights`(接受扁平数组,天然契合列式存储,无需构造中间对象);
- 时间轴用 P0 的 `points.time`;无时间戳的轨迹按累计里程等速合成虚拟时间(参考实现未处理,而国内平台导出的规划轨迹常无时间)。

### 3.3 相机引擎

移植 `flythrough.js` 三模式设计,改写为 TypeScript 并去除模块级可变状态(参考实现用模块级 `_state` 单例,不利于测试与多实例):跟随(相机位于运动点后上方,朝运动方向)、俯瞰(正上方缓慢环绕,滚轮调距)、自由(用户自由操控,运动点继续前进)。

相机路径基于 P0 的 `cumDist`,**以里程为参数而非帧序号**,保证倍速变化时轨迹一致——这也是 P2 逐帧渲染复用同一路径的前提。

### 3.4 HUD 数据源

HUD 数值全部来自 P0 已验证的统计模块(`stats/elevation.ts`、`stats/segments.ts`),**不在 3D 层另算一套**。验收标准第 6 条要求与 2D 剖面一致,即由此保证。

### 3.5 底图样式切换(V2 新增)

两种样式,两种模式下均可用:

| 样式 | 巡游模式(Cesium) | 规划模式(MapLibre) |
|---|---|---|
| **3D 卫星图** | Esri World Imagery(或 MapTiler 卫星)+ 3D 地形 | 卫星栅格瓦片,2D |
| **二维平面图** | 同一 Viewer 内切换影像图层 + 地形置为 `EllipsoidTerrainProvider` | 现有 OSM 栅格(P0 已有) |

设计要点:
- **不重建 Viewer**。通过 `imageryLayers` 增删与 `viewer.terrainProvider` 赋值切换,保留相机位置与巡游进度(验收标准 10)。Cesium 支持运行时替换 terrainProvider,但会触发地形重新请求,需处理切换期间的加载态。
- 影像 URL 沿用 §1.2 降级链;平面图在巡游模式下仍使用影像瓦片但关闭地形起伏,与「二维平面」语义一致。若需要真正的线划图(道路/注记),可接 Esri World Street Map 免费服务,列为 N6 可选项。
- 选择项分别持久化(规划模式与巡游模式各记一份,localStorage),与 P0 的分栏尺寸同属 UI 偏好,不进工程文件、不进撤销栈。

### 3.6 等高线图层(V2 新增)

**不采用**「另找一套等高线瓦片服务」的做法——免费且覆盖中国全境的等高线瓦片服务难以保证长期可用,且与 §1.2 已有的地形数据重复。

采用**基于已加载地形高程实时生成**的方案:
- 巡游模式:Cesium 提供 `ElevationBand` / 自定义材质路径,可对全局地形按高程着色并绘制等值线;首选以自定义地形材质(fragment shader 中按高程取模画线)实现,间距参数化;
- 规划模式(2D):P0 的 MapLibre 目前只有栅格底图,无高程数据。**规划模式的等高线列为 N6 可选项**,若实现,方案是复用 Esri 地形的 Terrain-RGB 形式瓦片经 MapLibre `hillshade`/自定义图层生成;评估后若成本过高则仅在巡游模式提供等高线,并在界面上明确说明。
- 间距自适应:按相机高度分档(如 <2km 用 10m 间距,2~10km 用 50m,>10km 用 100m),避免低空过密、高空消失。
- 可读性:等高线颜色与不透明度需同时适配卫星影像(暗底)与平面图(亮底),两种底图各配一组预设(验收标准 11)。

### 3.7 距离雷达(V2 新增)

**待确认的理解**:以当前位置为中心的同心距离圈(类似雷达罗盘),用于快速判断周边距离尺度。若实际需求是「距下一个 CP 的距离指示器」,设计需调整——开工前确认。

按同心距离圈理解的设计:
- 绘制在独立 Canvas 叠加层(`src/overlay/radar.ts`),不进入 Cesium 场景,因此不受 3D 相机俯仰影响、始终清晰;
- **圆心**:巡游模式为运动点在屏幕上的投影位置;规划模式为鼠标悬停点或地图中心;
- **量程自适应**:按当前屏幕比例尺选择一组"好看的"档位(100m / 250m / 500m / 1km / 2.5km / 5km / 10km …),每圈标注数值。档位选择与像素半径换算是纯函数,放 `radarMath.ts` 单测;
- **方位**:随相机朝向绘制北向指示与方位刻度;巡游跟随模式下相机朝向即前进方向;
- 与 HUD 同层,可独立开关,不与 CP 卡片重叠(布局上分区)。

## 四、里程碑

| 里程碑 | 内容 | 验收 |
|--------|------|------|
| N1 | Cesium 接入、viewer 与地形降级链、模式切换与按需加载 | 巡游模式能打开,地形可见,首屏体积不劣化 |
| N2 | 轨迹与 CP 的 3D 渲染、数据桥接层 | 33 万点轨迹贴地渲染流畅,颜色/粗细沿用 P0 |
| N3 | 巡游相机三模式、播放控制与倍速 | 1×~20× 平滑无跳变 |
| N4 | HUD 叠加层与 CP 卡片 | 数值与 2D 剖面一致 |
| **N6** | **底图切换、等高线、距离雷达(V2 新增)** | **交付物 10~12 全部达标;切换底图不丢失相机与巡游进度** |
| N5 | 视频录制与收尾验收 | 1080p WebM 可下载;验收记录归档 |

N6 排在 N5 之前:雷达与等高线属于画面内容,应在录制功能定稿前完成,否则录制的合成方式(§6 R8)要返工。

每个里程碑:TDD(可测部分)→ 自测 → 代码评审 → commit + tag(`p1-n1` … `p1-n6`,完成打 `v0.2.0`)。桥接层、抽稀、虚拟时间合成、相机里程参数化、雷达量程档位、等高线间距分档等纯逻辑必须单测;渲染与相机视觉效果由浏览器验收。

**N1 进度**:提交 `bd0f460`(Cesium 按需加载)、`4ee24d1`(viewer 与地形降级链,含单测)已完成,尚余模式切换与 FlyView 容器。

## 六、风险与应对

| # | 风险 | 影响 | 应对 |
|---|------|------|------|
| R1 | Esri / MapTiler 地形服务国内访问慢或不通 | 巡游模式不可用,与「离线优先」冲突 | 已初测可达(§1.2),**需真实国内网络复测**;不达标则评估恢复 PMTiles 地形烘焙 |

| R4 | 录屏画质不达传播要求 | 核心交付物打折 | P1 标注「预览级」;P2 做逐帧管线,相机路径已按里程参数化以便复用 |
| R5 | 无时间戳轨迹无法驱动时间轴 | 规划轨迹不能巡游 | 按里程等速合成虚拟时间 |
| R6 | Cesium 与 React 18 严格模式重复挂载 | Viewer 泄漏 | 明确创建/销毁生命周期,参照 P0 `MapView` 已验证模式 |

| **R8** | **雷达/HUD 在独立 DOM 层,不会被 `canvas.captureStream()` 捕获,录制视频里将不可见** | **视频缺失关键信息层,与方案 V2.1「信息叠加层」定位冲突** | **N6 即确定合成方案:录制时将叠加层绘制到一张离屏 Canvas,与 Cesium 画面合成后再 captureStream;此合成器同时是 P2 逐帧管线的基础,应一次做对** |
