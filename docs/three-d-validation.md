# TrailCraft Cesium 三维巡游验证记录

| 检查项 | 当前结果 | 说明 |
| --- | --- | --- |
| 三维入口 | 已接入 | 顶部“**三维巡游**”与任务轨道“**输出与巡游**”均会切换至 `FlyView`。 |
| Cesium 启动 | Viewer 已就绪，渲染待修复 | 状态栏已报告“地形：Esri · 影像：Esri”，说明 Viewer、Workers、地形与影像层均完成初始化；但页面出现 `InvalidStateError: The source image could not be decoded`，Cesium 停止渲染。低层级 Esri 卫星/街道瓦片经独立探测均返回 `image/jpeg`，因此下一步应为影像请求增加运行时降级与错误隔离，而不应把问题误判为静态资源缺失。 |
| ArcGIS 提供方替换 | 初始化等待中 | 已从手写瓦片模板切换至 `ArcGisMapServerImageryProvider`。网络日志显示 World Imagery 瓦片持续返回 200，但 Viewer 仍停留于加载态，因此后续排查聚焦于 Viewer 初始化时序与图层挂载，而非网络端点不可达。 |
| 动态模块边界 | 通过 | 浏览器性能记录显示 `viewer.ts`、`trackEntities.ts`、`cpEntities.ts`、`flythrough.ts`、`contours.ts`、`frameExport.ts` 与 Cesium 依赖均已加载；加载状态未结束的瓶颈发生在这些模块加载之后。 |
| 浏览器 JPEG 解码 | 通过 | 在同一预览浏览器中以 `fetch → Blob → createImageBitmap` 直接解码 Esri 0 级卫星瓦片，返回 `image/jpeg`、14,401 字节、宽度 256。问题不是基础 JPEG 不兼容，因此将 Viewer 改为先就绪、后异步挂载远程影像，避免影像服务初始化阻塞整个巡游界面。 |
| 非阻塞影像层 | 未通过 | Viewer 先就绪、后异步挂载 ArcGIS 影像层后仍出现同一渲染错误，说明需要先排除影像层是否为唯一触发条件。当前验证分支不挂载任何影像层，只保留地形、相机和路线实体。 |
| 无影像场景 | 仍失败 | 完全不挂载卫星、街道或网格影像后，Cesium 仍报同一 `InvalidStateError`。影像并非唯一触发条件；下一步隔离 Esri 高程地形提供方，并在不支持时显式降级为平面地球而非让渲染停止。 |
| 天空盒隔离 | 通过 | 禁用 Cesium 默认天空盒和大气贴图后，Viewer 进入就绪状态且不再出现图像解码错误。结论：当前环境中默认天空盒静态贴图是核心触发源。场景现以平面地球、相机与路线巡游核心运行；待恢复经验证的地形与影像层。 |
| 真实 GPX 巡游 | 通过（平面地形） | 导入 `速攀129新望京20240912160539.gpx` 后，三维控制台绑定 5,038 个轨迹点与 13.87 km 路线。点击播放会推进里程、海拔、坡度与心率 HUD；跟随/俯瞰/自由镜头、速度、画幅、1080p/4K、关键帧与视频导出入口均已出现。当前仍为“平面地形”降级，待为公众候选版本接入经验证的地形资源。 |
| Esri 地形恢复 | 通过 | 默认天空盒关闭后，重新启用既有 MapTiler → Esri → 平面链路；无 Key 情况下状态栏显示“地形：Esri · 影像：Esri”，真实 GPX 导入后巡游控制台、轨迹实体与指标均正常出现，未再出现图像解码错误。 |
| 相机与底图降级 | 验证中 | 已将巡游相机与运动标记的高度修正为“GPS 高程和已加载地形高程的安全上限”，防止不同高程基准导致镜头进入地表。另增加本地网格底图作为 Esri/MapTiler 瓦片延迟或不可见时的可视化降级，以避免黑屏掩盖路线和相机状态。 |
| 实况播放 | 通过（遥测） | 真轨迹三维播放已从 0.00 km 进入 0.46 km，HUD 同步更新海拔、坡度和心率；跟随、俯瞰与自由镜头入口均可操作。底图降级改动需在完整重新加载后复核画面可见性。 |
| 全新引擎启动 | 通过 | 完整刷新后 Cesium 引擎可在“地形：Esri · 影像：Esri”状态下完成就绪，并在未选择轨迹时给出明确的下一步提示；不再停留于加载态或报出静态天空纹理解码错误。 |
| 画布尺寸修复 | 已修复，待复测 | 浏览器检查发现 Cesium 画布被右侧长任务面板撑至约 4,187px 高，造成可视区域和相机画面异常。工作区已调整为受视口约束的固定高度，右侧面板改为内部滚动。 |
| 异步渲染修复 | 已实施，待复测 | 画布尺寸恢复后中心像素仍为纯黑，且无控制台错误；根因指向请求式渲染在远程地形与影像异步完成后没有触发新帧。Cesium 工作区现保持持续绘制，暂停和自动结束也不会中断场景刷新。 |
| 沙盒 WebGL 复核 | 受限 | 持续绘制后 WebGL 画布尺寸为 809×792、无 GL 错误，但中心像素仍为纯黑；真实轨迹的导入、相机控制与 HUD 遥测均正常。该无报错黑场未能在当前无头浏览器进一步定位，公众候选版本需在真实桌面和手机 GPU 浏览器上复核可视化效果。 |
| 空路线状态 | 已处理 | 右侧提示先导入并选择路线，避免在无活动路线时误导用户可直接生成巡游。 |
| 真实路线飞行 | 待验收 | 需导入真实 GPX 后检查路线实体、CP、相机、关键帧、等高线、雷达与导出控制。 |
