## 三、缺口与后续动作

原三项非功能缺陷中,以下两项已由用户补充的真实数据(`测试\补充测试轨迹数据\`)复测关闭;第三项(国内 App 坐标系样本)仍待补充:

1. ~~**FIT / KML 真实样本为零**~~ **已关闭**。补充了崇礼168 赛事路线 KML(`路线-崇礼_172_8km-7944m....kml`,官方 172.8km / 7944m)、四灵反穿路线 KML,以及两条真实 COROS 手表 FIT 录制。三个提交:
   - `fix(core): scope kml coordinate parsing to line geometry` —— 发现并修复了一个真实缺陷:`parseKml` 原先用文档全局的 `<coordinates>` 正则收集坐标,不区分几何类型,导致崇礼 KML 里 17 个 `<Point>` CP 标记的坐标被当成轨迹点尾随拼接进折线,里程从正确的 172.7km 虚高到 249.2km(+44%)。已修复为只从 `<LineString>`/`gx:Track` 等线几何取点。
   - `feat(core): import kml waypoints as checkpoints` —— 被排除的 `<Point>` CP 标记(含官方里程,如 `CP1二道营-12.5km`)进一步被导入为 CheckPoint 并锚定到轨迹上;13 个名称里带明确公里数的 CP,锚定里程与官方公里数误差均 <0.5km。
   - `fix(core): detect coros kml exports` —— COROS 的 KML/FIT 导出此前会被识别成 `unknown`(强制人工选择坐标系),现已通过 KML 里的 `<COROS>` 标签与 FIT 的 `file_id`(`manufacturer`/`product_name`)自动识别为 WGS-84/高置信。

   样本量仍只有 2 KML + 2 FIT(未达 5 条),验收标准 1b 因此仍标注"部分"。

2. **坐标系识别率无法测量**(仍未关闭)。识别率 ≥95% 的指标需要 GCJ-02 来源样本;现有真实样本全部是 COROS 设备的 WGS-84 轨迹(GPX 10 条 + 新增 KML/FIT 4 条),识别 14/14 正确但样本单一,不含任何国内 App 导出。
   → **需要**:两步路 / 六只脚 / 行者 / 奥维等国内 App 导出的轨迹文件。

3. ~~**爬升误差 ≤8% 未对照官方数据**~~ **已关闭**。崇礼168(172.8km / 7944m 官方数据)复测:解析出 38,509 个轨迹点,距离 172.68km(误差 -0.07%),爬升(项目默认平滑窗口 5 + 滞回阈值 5m)7562m(误差 -4.8%),在 ≤8% 验收标准之内。

## 四、已知限制(设计取舍,非缺陷)

- **底图**:使用 OSM 官方栅格瓦片,国内访问不稳定。瓦片 URL 已抽为常量便于替换;瓦片加载失败时应用会提示「底图瓦片加载失败,轨迹功能不受影响」,轨迹、剖面、CP 等全部功能不依赖底图。
- **KMZ**:不支持,导入时提示用户解压后导入 `doc.kml`。
- **拼接**:按轨迹列表当前顺序拼接,不支持拖拽排序;`joinTracks` 的活动轨迹解析仅在所选首条为活动轨迹时正确。
- **分割后的 CP 归属**:`splitAt` 产生两条轨迹,现全部 CP 重锚定到保留在原位置的前半段(·A),属于后半段的 CP 需人工复核。
- **关门时间时区**:`datetime-local` 输入按浏览器当前时区补写偏移量,跨时区编辑同一工程需注意。
- **坐标偏转合规**:GCJ-02/BD-09 转换为社区公开近似实现。方案 V2.1 已列明:面向国内商业发布前需完成测绘相关法规合规评估。

## 五、开发过程中修复的重要缺陷

浏览器验收与代码评审共发现并修复以下问题,均已提交:

| 缺陷 | 影响 | 提交 |
|------|------|------|
| 地图就绪判断用 `isStyleLoaded()`,依赖底图瓦片加载完成 | 国内瓦片不通时,轨迹图层、自动缩放、悬停标记全部静默失效 | `7b28aaf` |
| `Marker.addTo()` 先于 `setLngLat()` | maplibre v6 下必抛异常,悬停标记根本无法显示 | `7b28aaf` |
| 工具箱操作后 CP 不重锚定 | 抽稀后 `anchorIndex` 越界(如 200000 → 仅剩数千点) | `a5153a9` |
| 工具箱操作后 `activeTrackId` 被清空 | 连续操作断链 | `a5153a9` |
| 海拔正则不支持科学计数法 | 整列海拔被静默丢弃(非单点 NaN) | `cea603e` |
| `locateByDist` 在单点数组返回 −1 | 下游读取 undefined,静默传播 NaN | `8f4f1a9` |
| BD-09 转换缺 `outOfChina` 判断 | 境外坐标被错误偏移 600~900m | `525d76b` |
| 识别正则无词边界 | 如 "Snapple" 误匹配 "apple",高置信度下静默套用错误坐标系 | `cf54a2e` |
| FIT 无时间戳时产生全 NaN 列而非 undefined | 违反"整列缺失→undefined"约定 | `27889e2` |
