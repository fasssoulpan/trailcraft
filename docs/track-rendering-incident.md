# 轨迹渲染缺陷记录

日期：2026-08-20

用户报告：轨迹导入后，地图显示定位点和里程/高程读数，但不显示路线折线。

已在已发布候选版本打开二维路线工作台；MapLibre 画布正常创建。为使用仓库中的真实轨迹样例复现问题，已临时暴露页面中视觉隐藏但可访问的 `#trailcraft-route-import` 文件输入。下一步将上传真实 GPX，检查导入状态、MapLibre `trk-*` Source/Layer 以及相机定位。

已上传 `速攀129新望京20240912160539.gpx`。上传回调已进入“导入中…”状态；在此阶段地图仍处于默认视野。待解析完成后将检查状态是否写入、`trk-*` 图层是否创建及其绘制顺序。

已发布版本的 GPX 解析完成：工作台显示“已载入”、13.87 km、+824 m、5,038 点，轨迹列表亦生成“北京市 越野跑”。地图视野已定位到北京山区，但截图中卫星图上没有可见的路线折线，缺陷得到复现。

开发预览已切回二维模式。MapLibre 调试句柄显示：样式已加载、尚无 `trk-*` Source/Layer、无地图错误、默认中心为 `[104, 35]`、缩放级别为 `3`。这说明基线地图初始化正常，问题应在导入后的轨迹同步或图层视觉叠放阶段。

开发预览的隐藏导入输入已可定位，准备导入同一 GPX。这样可以用 `window.__trailcraftMap` 比较轨迹写入后 Source、Layer、绘制要素和相机状态，并与已发布版本的可见缺陷对照。

开发预览导入同一 GPX 后可见红色路线，中心移动至 `[116.1840, 40.0068]`。调试结果显示 `trk-trk_mt1015bd_0` 位于 `esri-satellite` 之后（顶层），Source 为 GeoJSON，且 MapLibre 无错误。由此确认导入解析、坐标与基础图层同步本身可工作；修复将增强路线图层的上层插入、样式可见性与导入后重试，以覆盖发布环境中的时序/样式竞争。

修复后在同一卫星底图上可见完整红色路线及其浅色对比轮廓。MapLibre 中仍存在 `trk-trk_mt1015bd_0`，SVG 叠加层生成两条轮廓线，地图无错误，中心及缩放保持在导入后的路线范围内。该策略同时保留 MapLibre 作为权威 GeoJSON/交互层，并提供不拦截鼠标事件的可见性保障。

最终验证：`pnpm check` 通过；生产构建成功完成，包含二维地图、Cesium 延迟运行时资源和路线可见性修复。实际 GPX 导入、指标更新、地图自动定位与路线显示闭环均已验证。
